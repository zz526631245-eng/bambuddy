# 开发路线图

## 总原则

先模拟、后虚拟打印机、最后单台真实机；阶段 14 前不连接真实打印机。每个阶段单独分支、单独测试、单独验收。

## 当前阶段状态

- 阶段 0～5：开发环境、源码审计和安全基线，已完成。
- 阶段 6：生产数据骨架、迁移和权限，已完成。
- 阶段 7：产品、图片、产品零件清单、材料类型、配置组和打印方案，已完成。
- 阶段 8：生产订单、需求拆解和数量账本，代码、GitHub CI 和人工验收均已完成。
- 阶段 9：产品源文件、版本失效、材料/颜色能力匹配和虚拟打印机自动分配，代码和本地回归已完成；GitHub CI/人工验收仍需由接手者按当前提交重新确认。
- 阶段 10：固定摆盘、自动摆盘、按数量拆盘、真实 sidecar 切片、切片缓存和切片库，代码和本地回归已完成；不发送打印。
- 阶段 11：虚拟打印状态流转、人工质检、合格/报废入账、清板释放和多盘整套判定，代码与本地聚焦回归已完成；等待用户人工验收，不发送打印。
- 阶段 12：直供耗材扫码绑定、耗材卷库、唯一二维码、入库/耗尽和材料类型统计已完成；等待用户人工验收。
- 阶段 13：打印机状态适配契约、心跳/离线判定、故障/维修模拟和不可用目标自动回收重排已完成；仍不连接真实打印机、不发送打印。

## 后续范围

- 阶段 9：系统自动匹配打印机配置并建立现有队列项；只做模拟分配，不连接打印机、不发送打印。
- 阶段 12：每台打印机维护一个当前直供耗材，固定扫码器扫描新耗材后自动替换旧记录；以颜色作为主要分配条件，AMS 保持可选。耗材卷库、批量唯一二维码、扫码入库/耗尽、库存统计和本地 HTTPS 手机测试入口已完成；等待用户验收。
- 后续阶段：材料预留、耗材匹配和不足提示，复用现有库存。
- 阶段 13：用统一状态快照接收虚拟/未来真实适配器的心跳，超过阈值自动离线；离线、故障、维修中目标不参与新分配，尚未开始的任务自动回到待分配并保留操作记录。
- 阶段 13 后续验收：在状态监控页面模拟空闲、打印中、离线、故障和维修，并观察任务回收重排。
- 阶段 14：单台真实打印机受控发送代码与本地回归已完成；用户需在一台真实打印机上完成手工验收后，才允许讨论扩展农场。
- 发布阶段：从全部测试通过的 Git 标签重新构建 Windows 安装包，并在干净电脑验证安装、升级和卸载。

后续阶段的具体内容在开工前根据当前真实代码再次冻结，不跨阶段一次开发多个大功能。
