# 下一阶段建议（由接手者先冻结范围）

阶段 10 已完成代码和本地验收。下一阶段不要直接连接真实打印机，也不要把阶段 14 的真实发送提前。

## 建议优先级

1. **质量与数量闭环**：盘任务完成/失败/报废、合格数量回写、清板等待和整套产品完成判定。多盘产品必须等同一产品套的全部源盘完成后才计为完成。
2. **耗材库存闭环**：预留材料和颜色，显示不足原因；复用现有库存模型，不另造库存系统。
3. **故障与重排演练**：只模拟打印机离线、切片失败、盘任务失败和重排，保留审计记录。
4. **操作员流程**：扫码、权限、审计、异常恢复和更清楚的订单/盘任务状态。
5. **阶段 14 受控真实机验收**：只有项目边界明确解除后，才允许单台真实打印机、受控发送和逐步扩展。

## 下一阶段不能改动

- 不改变阶段 7 的产品、图片和零件基础资料语义。
- 不恢复“旧打印方案/BOM 回退生产”；没有活动源文件必须拒绝订单。
- 不删除产品源文件版本、切片产物或历史订单快照。
- 不绕过现有打印队列、库存、权限和虚拟打印机模块。
- 不在阶段 14 前接入真实打印机通信或发送打印。

## 开工验收门槛

- 先为每个新增行为写失败测试。
- 运行阶段 7/8/9/10 回归、前端测试、构建、lint、Ruff 和 `git diff --check`。
- GitHub Actions 全绿后才考虑下一阶段人工验收；在此之前不构建对外 EXE。
